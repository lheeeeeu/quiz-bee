# 🏆 Real-Time Quiz Bee Competition System

A broadcast-grade, server-authoritative Real-Time Quiz Bee Competition System featuring three synchronized interfaces:

1. **Host/Admin Dashboard** (`/#admin`)
2. **Main Display Screen (Projector / TV)** (`/#display`)
3. **Individual Team Answering Pages (Up to 10+ Teams)** (`/#team` or `/?team=team-1`)

---

## 🌟 Key Features & Workflow Architecture

### 1. Step-by-Step Competition Workflow
- **A. Question Display**: When host clicks **"Display Question"**, the question and media immediately appear on the Main Display Screen and all 10 Team Answering Pages. The countdown timer is visible, but team answer inputs **remain strictly locked and disabled**.
- **B. Synchronized Timer**: When host clicks **"Start Timer"**, the server records the authoritative `timer_started_at` and `timer_ends_at` timestamps. The countdown starts simultaneously across all devices. Answering input textareas unlock instantly.
- **C. Automatic Answer Collection**: When the countdown reaches zero, the server immediately triggers answer locking. Inputs are disabled on client screens, and the server rejects any subsequent modifications. All drafted and final answers are automatically saved in the database.
- **D. Answer Evaluation & Scoring**: The Host Dashboard displays all collected answers side-by-side. The host can evaluate answers with 1-click **Correct** (configured points) or **Incorrect** (0 points), or apply manual score overrides.
- **E. Real-Time Leaderboard**: Main Display and Host screens transition to the live animated Leaderboard with accumulated point rankings, team avatars, and victory fanfare.
- **F. Next Question**: Host clicks **"Next Question"** to advance to the next round, seamlessly looping through the competition.
- **G. Dynamic Customization**: Add unlimited questions, create custom difficulty categories (Easy, Average, Difficult, Clincher, etc.), set custom points, custom timer durations, correct answer keys, trivia notes, and image attachments.

## 🛠️ Technology Stack & Architecture

- **Backend**: Node.js & Express with **Socket.IO** for zero-latency, multi-client real-time synchronization.
- **Database Engine**:
  - **Supabase Cloud PostgreSQL (`server/supabase-sync.js`)**: Configured via `.env` (`SUPABASE_URL` & `SUPABASE_PUBLISHABLE_KEY`). Automatically syncs rounds, questions, groups/teams, answers, event config, and session state to Supabase (`supabase/schema.sql`).
  - **Local Relational SQLite Cache (`data/quizbee.db`)**: Zero-latency offline-resilient local SQLite engine (Node `node:sqlite`, WAL mode, foreign keys, audit logs) with JSON Export/Import backups.
- **Frontend**: React 19 + Vite + Tailwind CSS + Lucide Icons + Canvas Confetti.
- **Audio Synthesizer**: Built-in Web Audio API synthesizer for countdown ticking, urgent pulses, buzzer, and victory fanfare without relying on external media files.

## 🚀 Quick Start Guide

### Prerequisites
- Node.js (v18+ recommended)
- npm (v9+)

### Installation & Run

1. Clone or navigate to the project directory:
   ```bash
   cd quiz-bee-system
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Build the frontend client:
   ```bash
   npm run build
   ```

4. Launch the Server:
   ```bash
   npm run dev
   ```
   The server will start on `http://localhost:3001`.

## 🛡️ Anti-Cheat & Reliability Measures

1. **Server-Authoritative Clock**:
   Timer end times are computed on the server (`timer_ends_at = started_at + duration_seconds * 1000`). Clients continuously synchronize against `serverTimeOffset`. Modifying local device clocks has zero effect.
2. **Server-Side Answer Rejection**:
   Submissions sent after `timer_ends_at + 1500ms grace window` are rejected by the server with `403 Timer Expired`.
3. **Continuous Draft Autosave**:
   Answers are automatically debounced and saved to the server as teams type. If a team's browser refreshes or their Wi-Fi momentarily drops, their answer is safe in the database and automatically collected.
4. **Duplicate Scoring Prevention**:
   Answers use a unique composite key `(question_id, team_id)`, preventing double scoring or score corruption.
